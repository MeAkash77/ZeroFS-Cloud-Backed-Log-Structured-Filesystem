02 / Why ZeroFS

Hide object-storage complexity behind a familiar filesystem.

01

POSIX-shaped access

Applications can work with files and directories instead of learning an object API. ZeroFS exposes NFS and 9P, plus NBD for block access.

02

Object-backed durability

File data and metadata live in the same object-storage system. No separate external database service is required.

03

Built-in data path

Extents are compressed, encrypted and packed into immutable segment objects before upload.

04

Tiered caching

Memory and disk cache tiers keep frequently accessed data close to the filesystem while object storage remains the durable backend.

05

High availability

Optional leader/standby replication uses the same bucket and supports automatic takeover with writer-epoch fencing.

06

Filesystem-grade testing

CI exercises POSIX suites, xfstests, kernel builds, stress workloads, ZFS and Jepsen-based recovery and HA scenarios.

03 / Architecture

Multiple access protocols. One filesystem core.

NFS, 9P, NBD and the browser Web UI converge on the same virtual filesystem layer, which then manages data segments, metadata and cache.

NFS CLIENTnative kernel filesystem access
NBD CLIENTraw block device + TRIM
9P CLIENTfilesystem protocol over TCP / socket
WEB BROWSERfile manager + dashboard + terminal
ZEROFS COREvirtual filesystem • segment store • LSM metadata • local cache
OBJECT STORAGES3 • GCS • Azure Blob • S3-compatible • local disk
04 / Data path

Watch one file become durable object data.

ZeroFS splits file contents into 32 KiB extents, compresses and encrypts each extent, then packs frames into immutable segment objects up to 256 MiB.

1. File → extents

A normal file becomes a stream of fixed-size data extents.

↓
file: dataset.bin
size: 1 GiB
extent: 32 KiB
layout: sequential extents

2. Extents → segment frames

Compression happens before encryption; frames are packed into immutable segments.

compress: zstd-3 / lz4
encrypt: XChaCha20-Poly1305
key derivation: Argon2id
segment: ≤ 256 MiB
metadata: LSM tree + extent pointers
↓
UPLOAD → immutable object
storage: S3-compatible bucket
